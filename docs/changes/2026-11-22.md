# Changes: 2026-11-22

## Docs: Redaction feature planning
- **Change:** Expanded REDACT-01 with popup-based phrase matching, native text selection and right-click redaction, rectangle redaction, secure full-save requirements and fail-closed verification.
- **Branch:** `docs/redaction-workflow-plan`
- **Commit scope:** `docs: detail secure redaction workflow`
- **Tests:** Documentation-only; no code or automated tests changed. Validation by diff review.

## Bugfix: Cross-page placed-item movement
- **Change:** Allow moving text boxes, signatures, notes and markup to other PDF pages while retaining editable annotation content and appearance. Edge scrolling supports dragging to offscreen pages; invalid drops are rejected.
- **Branch:** `bugfix/cross-page-placed-items`
- **Commit scope:** Placed-item service transfers, canvas drag handling, main-window drop routing, regression tests and cross-page compatibility rule in `AGENTS.md`.
- **Tests:** `tests/test_placed_items.py` and `tests/test_ui_smoke.py` cover cross-page moves, persistence and invalid destinations.

## Build: automatic version increment

- **Change:** Normal local builds bump the last version component once; `-Minor`, `-Secondary`, `-Major` and `-NoVersionBump` provide explicit choices. Project, package and installer versions stay aligned. Tagged installer workflow validates its fixed release version.
- **Branch:** `build/automatic-version-increment`.
- **Commit scope:** Version helper, Windows build launchers, release CI, dynamic version test, regression tests, build documentation and agent rules.
- **Tests:** `tests/test_versioning.py` (12 isolated tests passed locally; 94% version-helper coverage). Windows installer build and complete repository CI were not run locally.

## Build: manually triggered GitHub Releases

- **Change:** Added a manual GitHub Actions release selector that auto-increments the selected version (minor by default, secondary or major when selected), tests and builds the Windows installer, smoke-tests installation, generates a SHA-256 checksum, and publishes a release-specific changelog and installer to a public binary repository. Ordinary builds no longer increment automatically.
- **Branch:** `build/automatic-version-increment`.
- **Commit scope:** Windows release workflow, versioned installer name, changelog freezing and history checks, release tests, CI history enforcement, build docs.
- **Tests:** Added offline regression tests for version increments and for rejecting changes, deletion or rewriting of previously released changelogs. GitHub Actions and full Windows installer publishing need CI verification and public repository/token configuration.


## CI: publish installers in the public source repository

- **Change:** Point manual GitHub Releases publishing at the now-public `ertanturan/sabl-pdf` repository. Use the built-in `GITHUB_TOKEN` instead of release tokens and a separate repository. Push the tagged source before staging a release and explicitly dispatch CI for release-record PRs.
- **Branch:** `ci/publish-releases-in-source-repo`.
- **Commit scope:** Installer workflow, test workflow triggers, release routing tests, README, release plan, and agent rules.
- **Tests:** `tests/test_local_launchers.py` verifies the same-repository target, token permissions, correct tag order, and release-record CI dispatch. Full Windows CI to confirm.


## Bugfix: first GitHub Release preparation exits successfully

- **Change:** Avoid a failing missing-release query leaving PowerShell's native exit code at 1. List existing GitHub Releases with a success exit code instead, while still rejecting duplicate versions and API failures.
- **Branch:** `bugfix/release-lookup-exit-code`.
- **Commit scope:** GitHub Actions release lookup, workflow regression test, and current release notes.
- **Tests:** Add a release workflow regression test in `tests/test_local_launchers.py`. Run the full Windows CI pipeline and verify the manual release separately.
